## Where we start

`KERNELS.md` was checked against `main` (`5dbcc58`) on 2026-11-20: every ticked item exists in
the code, and no unticked item does. About 146 functions are left in P1-P3; P4 and P5 are out of
scope. Notes from the check:

- `gelu` and `silu` have `gelu_backward` / `silu_backward`, but no autograd node.
- `Tensor::zero_grad()` exists (global-norm clipping does not); autograd's internal
  `reduce_gradient` does what `sum_to_shape` would, but there is no public op.
- Possible autograd bug, read from `src/core/autograd.cpp` and not yet tested: backward does not
  run in topological order, so an intermediate tensor used twice (a residual connection, `x * x`)
  passes only its first gradient upstream. Leaf tensors (parameters) do accumulate correctly.
  Vedad's first item checks this.

## Dependencies

- Bakir's benchmark module and results database change how benchmarks are written. Until they land,
  write benchmarks as before ([BENCHMARKING.md](../BENCHMARKING.md)) so they are easy to move over.
- Vedad's `gelu` / `silu` autograd nodes and Aldin's new elementwise ops both edit
  `src/ops/elementwise.cpp`; say in the chat before you push, and merge `main` first.
- Vedad's `masked_select` and `nonzero` share the dynamic-shape rule; decide it once.
- Aldin's `accuracy` uses the existing `argmax` and comparisons; his label smoothing changes the
  `cross_entropy` kernel.
- Asja's `logsumexp` and `norm` reuse the stable maximum and double sums of `softmax` / `var`; the
  pooling and convolution items build on the existing `conv2d`, `avg_pool2d` and `max_pool2d`.

## Definition of done (same as before)

A sequential and a parallel version, dispatcher registration, public op, tests against a reference
in `tests/reference/`, a benchmark row, and a comparison with the best available implementation
(PyTorch, OpenBLAS and so on). See the [2026-11-04 plan](2026-11-04-plan.md) for the measuring rules.

To keep 100 functions possible: functions on a shared template (rounding, trig, logs, logical ops,
activations) can share one test file and one benchmark per family, with one row per function and
one PyTorch comparison run per family.

## Everyone, every time

- **Update [`docs/KERNELS.md`](../KERNELS.md)** in the same commit as the function: tick the box and
  add or change its row in "Current implementation status". A function not in `KERNELS.md` is not
  done.
- **Write a worklog** at the end of every working day in `docs/worklog/`, named
  `<name>-<dd>-<mm>-<yyyy>.md`, in the same form as before. Include the running count against your
  target.
- Merge `main` into your branch often; the files are shared (dispatcher, backend registration).
