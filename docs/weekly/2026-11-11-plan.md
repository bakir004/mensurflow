## Dependencies

- Aldin's `cross_entropy` needs his own `log_softmax`; its gradient needs `one_hot` (Bakir). Until it lands,
  build the one-hot inside the loss kernel.
- Aldin's attention uses Bakir's `gemm_strided_batched` and the existing `where`; it does not change them.
- Bakir's `dropout` needs his RNG; weight initialization (Xavier/He) later uses the same RNG.
- Vedad's `embedding` backward needs a scatter-add; he writes it as part of `embedding` and generalizes it in
  P2.
- Asja's `conv2d` forward and backward use the existing GEMM; the GEMM epilogue in P2 then speeds up
  `conv2d` + bias + ReLU.

## Same definition of done as last week

Sequential version, parallel version, dispatcher registration, public op, tests against a reference in
`tests/reference/`, a benchmark row, and a comparison with the best available implementation (PyTorch,
OpenBLAS and so on). See [last week's plan](2026-11-04-plan.md#same-definition-of-done-for-every-function);
the measuring rules there still apply.

Sequential and parallel: most existing kernels are one loop whose `MENSURFLOW_PARALLEL_FOR(if n > cutoff)`
runs on one thread below the cutoff; only `matmul`, `max`, `min` and the batched GEMM have separate
`_sequential` and `_parallel` functions. Bakir decides whether new functions need the separate pair.
