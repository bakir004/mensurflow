# Benchmark result: Asja, Ryzen 9 5900X, 2026-11-14

Parallel versions of `conv2d`, `max_pool2d`, `avg_pool2d`, `argmin`, `var` and `std` against their
sequential baselines, the hardware ceilings and the best reference available on this machine. Code:
commits `2ec0be0` to `035536d`; what each kernel does is in [KERNELS.md](../KERNELS.md).

## Ceilings (measured)

| | 1 thread | all cores |
|---|---|---|
| FMA peak (`fma_peak_benchmark`) | 111.7 GFLOP/s | 1261 GFLOP/s (12 threads); 1050 at 24 |
| Copy bandwidth, 64M floats (`bandwidth_benchmark`; read + write counted) | 17.8 GB/s | 36.1 GB/s |

The copy bandwidth counts each byte read and written; a pass that mostly reads (pooling forward,
`var`, `argmin`) can go above it, and inputs that fit in the 64 MB of L3 (every batch-1 case here)
are not limited by DRAM at all. So for the memory-bound ops the ceiling is approximate.

Reading: our whole convolution (im2col included) is faster than MKL's GEMM alone on every ResNet
layer, and faster than AOCL-BLIS's GEMM alone on the deep, wide layers (layer2-4, the 1x1 layers).

columns) by up to 1.6x even though its number has no im2col in it, and on very small products.

## What each optimization gained

Measured on the same machine; "before" and "after" differ only in the change named (except where a
row says "combined").

| change | measured on | before | after |
|---|---|---|---|
| `parallel_for` on the GEMM's thread pool instead of OpenMP (one set of spinning threads) | conv2d r18.layer1 N=1 forward, 12 / 24 threads (best of 30) | 2.63 / 3.38 ms | 1.75 / 1.96 ms |
| per-thread reused, uninitialized column buffer (no zero fill, no page faults per call) | same, 12 threads | 1.75 ms | 0.455 ms |
| 1x1 / stride-1 convolutions read the image as the column matrix (no im2col) | r50.layer1 N=1 forward, 12 threads (after the pool change) | 0.917 ms | 0.117 ms (the GEMM alone takes 0.119) |
| Auto strategy: one folded GEMM instead of image-per-thread at batch 32 | 7 ResNet layers, batch 32, 24 threads | per-image | folded 1.1x-1.7x faster on all 7 |
| backward: data per image, weight in fixed image groups or one folded GEMM (combined with the two above) | small layer N=32 backward, best | 0.451 ms (24 thr) | 0.372 ms (12 thr); r50.layer1 N=32: 49.4 → 13.6-15.0 ms |
| pooling: locals instead of reads through captures, window ranges per call, `v != v` for NaN | ResNet stem pool N=1, parallel on 1 thread | max fwd 2.07, max bwd 0.611, avg bwd 3.52 ms | 1.71, 0.187, 1.57 ms |
| var/std: 8 interleaved Welford lanes (contiguous) and 256 outputs at once (strided), reciprocal per step | parallel on 1 thread vs sequential Welford | layer-norm 27.2 ms, batch-norm 36.8 ms | 4.5-6.5 ms, 3.1 ms |
| conv below the cutoff through the per-image code on one thread | small layer N=1 | fwd 0.065, bwd 0.133 ms | 0.052, 0.095 ms |

## Stability and noise

- Most rows agree within 5% between the two runs; the cells show both.
- **Noisy (do not read single numbers):** every 24-thread row (two threads per core; the OS
  placement varies); `std` on the layer-norm and batch-norm shapes at 12 threads (0.40 vs 0.76 ms,
  0.34 vs 0.58 ms between runs); `argmin` k-means at 24 threads (2.4 ms in one run, 0.30 ms in the
  other); global max pooling at batch 32 on 24 threads (one run showed 2.1 ms against 0.05-0.1);
  avg-pool backward 2x2/2 N=1 at 12 threads (0.088 vs 0.055 ms); conv sequential rows at batch 32
  (up to 15% apart, e.g. layer1 157 vs 135 ms).
- The machine was not checked for background load, so differences under about 5% mean nothing.

## Not reached / open

- **PyTorch not compared**: no Python on this machine. Run `benchmarks/reference/conv_pool.py` and
  `argmin_var_std.py` where PyTorch is installed (same shapes, threads and columns). PyTorch's x86
  convolution uses oneDNN, which is not available here either, so AOCL's and MKL's GEMM-only numbers
  are the closest reference.
- conv2d behind AOCL's GEMM on conv1 and layer1 (0.64-0.89x): with short depth (K = 147, 576) and
  many columns, im2col is a large part of the time and our GEMM is at 300-450 GFLOP/s. Next: im2col
  into the GEMM's packed B layout directly (skipping the column matrix), or a direct convolution for
  3x3 stride 1.
- Small convolutions: the packed GEMM runs at about 23 GFLOP/s on m = 16, n = 256, k = 144 (AOCL
  97, MKL 80); that is a matmul small-size issue, not a conv one.
- Global pooling at batch 1 (49 elements per window, 512 windows): the parallel backward is 0.36x
  (avg) and 0.61x (max) of the sequential one because the work is a few microseconds; a cutoff that
  sends such shapes to the sequential kernels would fix it.
- Max-pool backward scales only 2-3.5x at batch 32 (one task per plane, a scatter); a gather by input
  row (as avg-pool has) would need indices known to lie in their window.
