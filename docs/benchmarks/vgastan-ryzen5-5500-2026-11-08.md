## What is compared

| MensurFlow area | PyTorch reference | NumPy reference |
|---|---|---|
| Activation backward | `torch.autograd.grad` over ReLU, sigmoid, tanh, GELU, and SiLU | Analytical float32 formulas |
| Transpose and permutation materialization | `tensor.t().contiguous()` and `tensor.permute(...).contiguous()` | `numpy.ascontiguousarray` |
| `index_select` | `torch.index_select` | `numpy.take` |
| `gather` | `torch.gather` | `numpy.take_along_axis` |

The script uses float32 inputs, checks results before timing, uses preallocated or
view-compatible operations where the reference API permits it, pauses 500 ms between
libraries, and reports median, minimum, and maximum of nine samples. PyTorch is
measured across the same thread sweep used by the repository benchmarks; NumPy is
the single-thread reference.

### Direct MensurFlow comparison

The native Release
[`activation_movement_benchmark`](../../benchmarks/activation_movement_benchmark.cpp)
ran the same float32 shapes through MensurFlow's public APIs. Ratios are
`ours / reference`: below 1.00x means MensurFlow was faster.

| Operation | Ours ms | PyTorch ms | Ours/PyTorch | NumPy ms | Ours/NumPy |
|---|---:|---:|---:|---:|---:|
| ReLU backward | 0.9234 | 0.6281 | 1.47x | 1.8084 | 0.51x |
| Sigmoid backward | 6.5662 | 1.5537 | 4.23x | 11.6471 | 0.56x |
| Tanh backward | 5.7219 | 3.1776 | 1.80x | 5.3822 | 1.06x |
| GELU backward | 12.6867 | 2.1189 | 5.99x | 198.4178 | 0.06x |
| SiLU backward | 6.8221 | 2.4613 | 2.77x | 18.1948 | 0.37x |
| Transpose contiguous | 15.5680 | 5.9946 | 2.60x | 22.1576 | 0.70x |
| Permute contiguous | 12.1534 | 7.4576 | 1.63x | 6.0906 | 2.00x |
| Index select | 3.1121 | 0.3715 | 8.38x | 4.5844 | 0.68x |
| Gather | 5.5435 | 0.9991 | 5.55x | 3.8804 | 1.43x |

These are public API timings including result allocation on both sides.
Correctness was checked before timing. The post-optimization native medians above
include contiguous fast paths for selection/gather and tiled transpose staging;
the generic strided fallbacks remain available for other layouts.

The CPU kernels use OpenMP through the `MENSURFLOW_PARALLEL_FOR` macro. Its
`if` clause keeps small workloads on the calling thread, while larger workloads
are split across the OpenMP team. `cpu::set_max_threads()` controls the maximum
team size; builds without OpenMP run the same loops serially.
