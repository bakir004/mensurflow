Author: Aldin, with Codex assistance. These are the six RNG/indexing functions taken over from
Bakir's row in the [weekly plan](../weekly/2026-11-11-plan.md), including both backward operations.

## Machine and build

- AMD Ryzen 5 6600H, 6 physical cores / 12 hardware threads, 16 MiB L3, Ubuntu 24.04.4 x86-64.
- GCC 13.3.0, C++17 library (C++20 when required by the optional LibTorch target), Release,
  OpenMP 4.5, `MENSURFLOW_NATIVE=OFF`, CUDA/Metal/OpenBLAS disabled.
- Native reference: PyTorch/LibTorch **2.15.0+cpu**, ATen OpenMP; the wheel includes MKL 2024.2.
  Both libraries request 1, 2, 6 and 12 intra-op threads; Torch inter-op threads = 1.
- `OMP_DYNAMIC=FALSE`, `OMP_PLACES=cores`, `OMP_PROC_BIND=spread`. AC power was online and the
  CPU governor was `performance`. Other desktop applications were not controlled.
- Source baseline `a926230`, with this change on `aldin-branch`. Full tests passed before timing:
  **31/31 OpenMP (36.08 s)** and **31/31 without OpenMP (34.59 s)**.

## What is timed

The shared `bench.hpp` harness times public CPU APIs against native allocating ATen calls.
Allocation, argument validation and operation execution are included on both sides. Input tensor
construction, host readback, checks, checksums and autograd recording are excluded. This differs
from the preallocated activation comparison and its raw times should not be compared here.

Each row has one warm-up, calibration and **nine measured samples**, even for slow calls.
Median, minimum, maximum and throughput remain in the raw logs. Each measured library has a
500 ms settling pause. Run 2 reverses library order after cooling the machine.

| Operation | Conditions |
|---|---|
| `uniform` | F32, range [-1,1), seed 20261111 and sample offset 0 |
| `normal` | F32, mean 0, standard deviation 1, same seed/offset |
| `bernoulli` | F32 zeros/ones, probability 0.25 |
| `dropout` | F32 input/output, saved Bool mask, training, probability 0.25 |
| `dropout_backward` | Same predetermined Bool mask and F32 upstream gradient on both sides |
| `one_hot` | I64 input/output, 16 classes; target sizes round up to complete rows |
| `embedding` | F32 512×32 table, I64 indices with repeats; target sizes round up to 32 features |
| `embedding_backward` | F32 upstream gradient, repeated I64 indices; output is always 512×32 |

RNG streams differ: MensurFlow uses Philox4x32-10 and PyTorch uses its CPU generator. Bounds and
distribution moments are checked independently, without claiming sample equality. Dropout checks
its mask values, keep frequency and output formula. One-hot and both embedding directions are
checked against independent deterministic references, including nonuniform upstream gradients.
The benchmark validates shape/dtype before reading results. All checks precede timing.

### Slow and uncertain cases

**Normal:** the portable Box-Muller path uses scalar double-precision `log`, `sqrt`, `sin`
and `cos`, plus ten Philox rounds. GCC diagnostics do not show a vectorized generation loop.
The stable single-thread and two-thread deficits, including the 32,769-element case, point
to work inside each block rather than a missing parallel implementation. A future pass can
vectorize Philox batches and the transform while retaining sample-offset/chunk semantics;
no global ISA flags, fast-math changes or tuned thresholds were introduced here.

**Small embedding backward:** the 32x32 upstream case at 6 and 12 requested threads is
about 2x behind PyTorch in both runs. The kernel stays below its parallel cutoff, but still
allocates/counts/prefix-sums stable buckets for 512 vocabulary rows and initializes the whole
table. At this size fixed grouping/validation costs dominate. A direct serial scatter-add
path below the cutoff is a candidate for a later measured optimization.

**Other varying rows:** public allocation, conditional threading, CPU placement and desktop
load can affect the observed memory-bound and small-input times. This run does not isolate
their causes. Retain both results, repeat the flagged conditions in a controlled session,
and do not use them to select new defaults. SIMD evidence here is compiler diagnostics,
not a measured SIMD speedup.
