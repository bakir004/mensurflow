## What I did

1. **`conv2d`** (`include/mensurflow/ops/conv.hpp`, `src/backends/cpu/ops/conv/conv2d.*`).
   NCHW, `weight[C_out, C_in, kH, kW]`, optional bias (pointer), stride and zero padding per
   dimension; dilation and groups other than 1 are rejected; output
   `floor((H + 2p - k) / s) + 1`, rejected below 1. One image at a time: im2col, then the
   single-threaded packed GEMM (`matmul_f32_packed_strided`). The backward passes use the strided
   entry point to read `weight^T` and `cols^T` in place, without transposed copies. The weight
   gradient sums the per-image products over the batch; the bias gradient sums in double.
2. **`max_pool2d`** (`src/backends/cpu/ops/conv/pooling.*`). Returns `{output, indices}`; indices
   are I64 positions `ih * W + iw` within each plane (as PyTorch). Padding never wins, ties go to
   the first cell in row-major order, NaN as in `argmax`/`max` (first NaN wins). Stride defaults to
   the kernel (`{0, 0}`); padding at most half the kernel (PyTorch's rule, so every window has an
   input cell). Backward scatter-adds through the indices; autograd keeps a private copy of them.
3. **`avg_pool2d`**. Padding counts in the divisor (`count_include_pad = true`, PyTorch's
   default) and `ceil_mode = false`, so the divisor is always `kH * kW`; window sums in double.
4. **`argmin`**. Same axis support (last axis only), tie rule and NaN rule as `argmax`; the two
   now share one validation helper.
5. **`var`**. Any axis, `keepdim`, `correction` (default 1 as PyTorch, 0 = population). One pass
   with Welford (mean and M2 in double). `count - correction <= 0` (one element with correction 1,
   an empty axis) gives NaN, and a NaN gradient.
6. **`std`**. `sqrt(var)` with the same conventions; its gradient is 0 where the std is 0 (as
   PyTorch), NaN where `count - correction <= 0`.
7. **Shared test pieces**: `tests/gradient_check.hpp` (deterministic test data, tolerant
   comparisons naming the first bad index, central-difference gradients of
   `L = sum(f(x) * w)`, and `L` as an autograd scalar); references `tests/reference/conv.hpp`
   (direct loops in double), `pooling.hpp` (windows walked over their full extent, padding skipped
   explicitly), and `reduction.hpp` (`argmin`, two-pass variance and its gradients).

### Tests

- Every function against its reference on odd and non-square sizes: stride above 1, padding above
  0, 1x1 kernels, kernels as large as the (padded) input, batch 1 and a single channel, strides that
  do not divide the span; for `var`/`std` every axis of ranks 1 to 4, `keepdim` and corrections 0, 1
  and 2.
- API cases: empty batch, no channels, no input channels (gives the bias), empty axes; views
  (NHWC permuted to NCHW, sliced weights and biases, transposed gradients, expanded rows); every
  validation error.
- Every backward: a central finite-difference check on small inputs, a check against the reference
  backward, and the same through autograd (including a gradient through a permuted view, and only
  some parameters requiring gradients). Max pooling uses inputs whose values are 0.1 apart for the
  finite differences, so a step cannot change the winner.
- `var`/`std` hard case: `1e8 + 8 * {0, 1, 2, 3}` (1000 values, exact in float32, variance
  80.08). The naive `sum(x^2) - n mean^2` is off by 0.16% in double and meaningless in float; the
  test asserts both, so it really is a hard case, and that Welford is within 1e-6.
- Mutation checks, each made by hand and reverted: col2im overwriting instead of adding, `>=` in
  the max-pool tie rule, the average divisor without padding, and the naive variance formula in
  place of Welford. Each one failed its test.
- Full suite: **36/36 tests pass** (Release, MSVC 14.51, OpenMP on, Ryzen 9 5900X, about 54 s), no
  compiler warnings in the new code.

## Not done / open

- Parallel versions, cutoffs, benchmarks and the PyTorch comparison (next phase).
- `conv2d`: no dilation, groups, `padding = "same"` or other padding modes; float32 only. The
  im2col buffer holds one image (`C_in * kH * kW * H_out * W_out` floats), which is large for early
  ResNet layers with a big batch only in time, not memory, since it is per image.
- Pooling: 4-D input only (no unbatched `[C, H, W]`), no `ceil_mode`, no `count_include_pad = false`
  or `divisor_override`, no dilation for max pooling.
- `argmin`: last axis only, like `argmax`.
- `var`/`std`: no whole-tensor overload (reshape to 1-D), integer `correction` only; for
  `count - correction <= 0` we always return NaN, where PyTorch returns inf for some of those cases.
- `mensurflow::std` shares its name with the standard namespace; it is legal C++ and compiles, but
  callers have to qualify it. Renaming it (e.g. `stddev`) is an option if the team prefers.
