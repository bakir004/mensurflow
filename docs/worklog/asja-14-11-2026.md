## What I did

1. **`conv2d`** (`include/mensurflow/ops/conv.hpp`, `src/backends/cpu/ops/conv/conv2d.*`).
   NCHW, `weight[C_out, C_in, kH, kW]`, optional bias (pointer), stride and zero padding per
   dimension; dilation and groups other than 1 are rejected; output
   `floor((H + 2p - k) / s) + 1`, rejected below 1. One image at a time: im2col, then the
   single-threaded packed GEMM (`matmul_f32_packed_strided`). The backward passes use the strided
   entry point to read `weight^T` and `cols^T` in place, without transposed copies. The weight
   gradient sums the per-image products over the batch; the bias gradient sums in double.
2. **`max_pool2d`** (`src/backends/cpu/ops/conv/pooling.*`). Returns `{output, indices}`; indices
   are I64 positions `ih * W + iw` within each plane (as PyTorch). Padding never wins, ties go to
   the first cell in row-major order, NaN as in `argmax`/`max` (first NaN wins). Stride defaults to
   the kernel (`{0, 0}`); padding at most half the kernel (PyTorch's rule, so every window has an
   input cell). Backward scatter-adds through the indices; autograd keeps a private copy of them.
3. **`avg_pool2d`**. Padding counts in the divisor (`count_include_pad = true`, PyTorch's
   default) and `ceil_mode = false`, so the divisor is always `kH * kW`; window sums in double.
4. **`argmin`**. Same axis support (last axis only), tie rule and NaN rule as `argmax`; the two
   now share one validation helper.
5. **`var`**. Any axis, `keepdim`, `correction` (default 1 as PyTorch, 0 = population). One pass
   with Welford (mean and M2 in double). `count - correction <= 0` (one element with correction 1,
   an empty axis) gives NaN, and a NaN gradient.
6. **`std`**. `sqrt(var)` with the same conventions; its gradient is 0 where the std is 0 (as
   PyTorch), NaN where `count - correction <= 0`.
7. **Shared test pieces**: `tests/gradient_check.hpp` (deterministic test data, tolerant
   comparisons naming the first bad index, central-difference gradients of
   `L = sum(f(x) * w)`, and `L` as an autograd scalar); references `tests/reference/conv.hpp`
   (direct loops in double), `pooling.hpp` (windows walked over their full extent, padding skipped
   explicitly), and `reduction.hpp` (`argmin`, two-pass variance and its gradients).

### Tests

- Every function against its reference on odd and non-square sizes: stride above 1, padding above
  0, 1x1 kernels, kernels as large as the (padded) input, batch 1 and a single channel, strides that
  do not divide the span; for `var`/`std` every axis of ranks 1 to 4, `keepdim` and corrections 0, 1
  and 2.
- API cases: empty batch, no channels, no input channels (gives the bias), empty axes; views
  (NHWC permuted to NCHW, sliced weights and biases, transposed gradients, expanded rows); every
  validation error.
- Every backward: a central finite-difference check on small inputs, a check against the reference
  backward, and the same through autograd (including a gradient through a permuted view, and only
  some parameters requiring gradients). Max pooling uses inputs whose values are 0.1 apart for the
  finite differences, so a step cannot change the winner.
- `var`/`std` hard case: `1e8 + 8 * {0, 1, 2, 3}` (1000 values, exact in float32, variance
  80.08). The naive `sum(x^2) - n mean^2` is off by 0.16% in double and meaningless in float; the
  test asserts both, so it really is a hard case, and that Welford is within 1e-6.
- Mutation checks, each made by hand and reverted: col2im overwriting instead of adding, `>=` in
  the max-pool tie rule, the average divisor without padding, and the naive variance formula in
  place of Welford. Each one failed its test.
- Full suite: **36/36 tests pass** (Release, MSVC 14.51, OpenMP on, Ryzen 9 5900X, about 54 s), no
  compiler warnings in the new code.

## Phase 2: parallel versions and performance

Following points 2, 5 and 6 of the [definition of done](../weekly/2026-11-04-plan.md#same-definition-of-done-for-every-function).
Full tables, method and noise notes:
[docs/benchmarks/asja-ryzen9-5900x-2026-11-14.md](../benchmarks/asja-ryzen9-5900x-2026-11-14.md).

### What I did

1. **`parallel_for` / `parallel_sum` / `parallel_reduce`** (`src/backends/cpu/parallel.hpp`): the
   only place with pragmas. Pieces are fixed by the problem size, never by the thread count, so
   every new parallel kernel gives the same bits at every thread count. The pieces run on the
   packed GEMM's thread pool (OpenMP only as a fallback): with two sets of spinning workers, im2col
   and the GEMM stole each other's cores.
2. **`conv2d_*_f32_parallel`**. Forward: one large GEMM over a chunk of the batch (column matrix at
   most 32 MB) or whole images per thread when there is at least one small image per thread (both
   give the same bits); 1x1/stride-1 layers use the image itself as the column matrix. Backward
   data: per image or folded, col2im with one task per (image, input channel) plane, so no races.
   Weight: fixed image groups (small gradients) or one folded GEMM per chunk, partial sums added in
   order, no atomics. Per-thread reused, uninitialized buffers. Small convolutions run the same
   per-image code on one thread.
3. **`max_pool2d` / `avg_pool2d` parallel**: forward one task per (plane, output row); max backward
   one task per plane (race-free scatter through the saved indices, exactly the sequential bits);
   avg backward gathers per (plane, input row) in the sequential scatter's order.
4. **`argmin` parallel**: rows across threads, long rows in 16K blocks merged with the first-minimum
   and first-NaN rules; exactly the sequential indices.
5. **`var` / `std` parallel**: fixed blocks along the axis merged with Chan's formula; 8 interleaved
   Welford lanes on a contiguous axis, 256 outputs at once on a strided one.
6. **Benchmarks**: `conv2d_benchmark` (ResNet-18/50 layers and a small one, batch 1 and 32, forward
   and backward, plus MKL / AOCL-BLIS sgemm on the same products), `pooling_benchmark`,
   `argmin_var_std_benchmark`; PyTorch scripts `benchmarks/reference/conv_pool.py` and
   `argmin_var_std.py` with the same shapes and columns.

### Benchmarks and results (Ryzen 9 5900X; two runs each; ceilings measured today)

Ceilings: FMA peak 111.7 GFLOP/s per core, 1261 on 12 cores; copy bandwidth 17.8 GB/s on one
thread, 36.1 GB/s on all.

- **conv2d**: 7-17x over sequential at 12 threads. Best: ResNet-18 layer4 at batch 32, 886 GFLOP/s
  forward and 930 backward (70-74% of the FMA peak); batch 1 layers 390-670 GFLOP/s.
- **Reference comparison (conv2d)**: PyTorch **not compared** (no Python on this machine). Against
  the vendor GEMMs on the same products *without* im2col: we are faster than MKL 2026.2 on all 14
  ResNet cases (1.08x to 3.18x); against AOCL-BLAS 5.2.0 we are 1.02x to 2.05x on layer2-4 and the
  1x1 layers, and **behind on conv1 and layer1 (0.64x to 0.89x)** and on the tiny layer (0.23x, a
  GEMM small-size issue).
- **Pooling**: 10-25x over sequential; the batch-32 stem pool reaches 29-34 GB/s, 85-95% of the copy
  bandwidth. Max-pool backward at batch 32 only 2-3.5x (one task per plane).
- **argmin**: 14-15x on 1024 x 1000 and long rows (53 GB/s); 1.3x on tiny inputs.
- **var / std**: 4-12x faster than the sequential Welford already on one thread (lanes, reciprocal);
  up to 110x at 12 threads; the 64 MB vector reads at 53 GB/s.

What each optimization gained (details in the result file):

| change | gain |
|---|---|
| `parallel_for` on the GEMM pool instead of OpenMP | conv layer1 N=1: 2.63 → 1.75 ms (12 thr), 3.38 → 1.96 ms (24 thr) |
| reused uninitialized column buffer | 1.75 → 0.455 ms (3.8x) |
| 1x1 conv without im2col | r50.layer1 N=1: 0.917 → 0.117 ms (= the GEMM alone) |
| folded GEMM as the default at batch 32 | 1.1-1.7x on all 7 ResNet layers vs image per thread |
| pooling: locals, per-call window ranges, `v != v` | stem pool 1 thread: max bwd 0.611 → 0.187, avg bwd 3.52 → 1.57 ms |
| var/std lanes and strided layout | 1 thread: 27.2 → 4.5-6.5 ms (layer-norm), 36.8 → 3.1 ms (batch-norm) |
| small conv through per-image code | backward 0.133 → 0.095 ms |

**Noisy:** all 24-thread rows; `std` at 12 threads (up to 1.9x between runs); argmin k-means at 24
threads; global max-pool at batch 32 on 24 threads (one outlier run); conv sequential rows at
batch 32 (up to 15%). Background load was not checked; read <5% differences as noise.

### Problems found and fixed

- OpenMP and the GEMM pool spinning against each other (see above); a 7 MB zero-filled vector per
  call (single-threaded fill plus page faults) that cost more than the GEMM.
- MSVC without type-based alias analysis: loops reading sizes and pointers through lambda captures
  ran 2x slower than the same loops in the sequential kernels; fixed with locals.
- `std::isnan` in hot loops under MSVC; replaced by `v != v` in the parallel kernels.
- Working tree files are CRLF (autocrlf): multi-line `perl`/`sed` replacements silently did
  nothing twice; used the editor tools instead.
