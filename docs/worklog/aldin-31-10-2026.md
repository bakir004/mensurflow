## 3. Implemented operations

| Operation | Behavior |
|---|---|
| `neg(x)` | Negate each element. |
| `abs(x)` | Clear the sign, including negative zero. |
| `square(x)` | Multiply each element by itself. |
| `relu(x)` | Replace negative values with positive zero; preserve NaNs and signed zeros. |
| `sqrt(x)` | Float32 square root; negative inputs produce NaN. |
| `exp(x)` | Float32 exponential, including overflow and underflow behavior. |
| `sigmoid(x)` | Stable logistic formula that avoids exponential overflow for finite inputs. |
| `axpy(alpha, x, y)` | Fused float32 `alpha*x + y`, with broadcasting. |
| `bias_add(x, bias)` | Add a compact `[features]` bias to each row of `[batch, features]`. |

All nine operations have a plain sequential version and a parallel version using `parallel_for`.
AXPY uses `std::fma` so multiplication and addition have one final rounding. Bias addition keeps
the bias vector compact and processes contiguous row spans, including thread blocks that start
inside a row.

Kept the implementations in `src/backends/cpu/elementwise.hpp/.cpp` and `sequential.hpp/.cpp`.
After reviewing the structure, grouped negation with the other operations instead of retaining
separate per-operation files. No new test executables or CMake source entries were needed.

## 6. Benchmarks and cutoff investigation

Extended `benchmarks/cpu_parallel_benchmark.cpp` with `sub`, `div`, and the nine new operations.
The benchmark now covers 14 operations including the existing `add`, `mul`, and `dot`.
Added operation-name filters so a run can measure only selected functions.

- Included the required sizes: 100,000; 200,000; 500,000; 1,000,000; 2,000,000; and 5,000,000.
- Also measured small inputs, 32,768/32,769 cutoff probes, and larger arrays.
- Compared 1, 2, and 4 threads first, then extended comparisons to 6, 8, and 12 threads.
- Retained preallocated buffers, warmup, repeated calls, median-of-nine sampling, and the existing
  staggered array offsets used to reduce the earlier 4K-aliasing problem.
- Timed kernels separately from Tensor allocation, dispatch, and input packing.
- Used nonnegative inputs for the square-root benchmark and recorded AXPY's coefficient and the
  matrix/bias shape policy. Every timed parallel result was checked against its sequential result.

Machine: **Acer Nitro AN515-46**, AMD Ryzen 5 6600H, 6 cores / 12 hardware threads,
approximately 14.8 GiB usable RAM, Ubuntu 24.04.4 LTS, GCC 13.3.0.
Official measurements used Release with `MENSURFLOW_NATIVE=OFF` and GPU backends disabled.
AC power and the `performance` CPU governor were recorded for the later runs; background activity
was not controlled, and the earliest power conditions were not recorded.

Repeated noisy measurements with core binding (`OMP_PROC_BIND=SPREAD`, `OMP_PLACES=cores`).
Also explored higher cutoff candidates around 262,144 and 524,288 in temporary probes.
These investigations did not produce an adopted cutoff change: the shared threshold remains
**32,768 elements**, and the documented results remain provisional.

The main observation is that useful thread counts depend on the operation and input size.
Large simple elementwise operations often approach the memory limit, while math-library costs
also affect `exp`, `sigmoid`, and fused AXPY. Twelve threads were not consistently fastest.
