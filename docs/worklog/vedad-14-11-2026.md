## What I did

1. **Optimizers** (`src/backends/cpu/ops/optimizer.cpp`, `src/ops/optimizers.cpp`): one fused loop per op,
   in place, PyTorch's formulation (Adam's bias correction and epsilon placement now match: the draft put
   epsilon outside the bias correction). Bias corrections in double, so a large step count stays finite.
   Validation throws before anything is modified: shapes, dtype, device, contiguous parameter, state
   tensors that share storage with each other or the parameter, steps below 1, bad betas/epsilon/decay. A
   strided gradient is packed. The same bits at every thread count.
2. **layer_norm / rms_norm** (`normalization.cpp`): one thread per line, line sums in eight float lanes
   combined in double (SSE2 intrinsics with a portable fallback of identical lane order), two-pass variance
   (accurate for a large common offset). `normalized_shape` may span several trailing dimensions. Backward
   recomputes mean/rstd; weight and bias gradients are summed in at most 64 blocks whose layout depends only
   on the shape, so every thread count gives the same bits. Optional weight and bias.
3. **batch_norm**: NCHW (`[N, C, ...]`) is parallel over planes, `[N, C]` over blocks of rows; statistics are
   per-channel sums added in a fixed order. Training uses the biased variance to normalize and the
   **unbiased** one for the running variance (as PyTorch; the draft used the biased one); it needs two or
   more values per channel. Eval uses the running statistics. The old backward did its statistics in
   single-threaded host code through `to_vector`; it is now one kernel. The public
   `batch_norm_backward` lost its unused `momentum` argument.
4. **Autograd** for `layer_norm`, `rms_norm` and `batch_norm` (input, weight and bias; the graph keeps its
   own copy of the running statistics in eval mode, because the caller may keep updating them). The
   optimizers record nothing: they are the step after `backward()`.
5. **Tests** (`tests/ops/optimizer_normalization_test.cpp`, with `tests/reference/`): known answers
   generated from PyTorch 2.15 (`optimizer_normalization_torch.py` writes the header, so the test does not
   need PyTorch); double-precision references, with the normalization gradients written as full Jacobians
   that share nothing with the kernels, and checked in turn against finite differences; sizes around the
   32768-element cutoff and thread counts 1, 2, 3 and all, bitwise equal across them; strided and
   transposed views, empty tensors, NaN/Inf in one line, constant lines, a 1e4 common offset, every
   error leaving the state untouched, autograd for every op in train and eval. I checked that the tests
   catch bugs by breaking the code four ways (Adam epsilon form, biased running variance, a missing term in
   the layer-norm gradient, a thread-dependent block count): each failed with a clear message.
6. **Benchmark** (`benchmarks/optimizer_normalization_benchmark.cpp`): rewritten. The draft reset its state
   and allocated inside the timed region and covered 3 of 9 ops. Now: all nine, sequential vs parallel with
   a bitwise check across thread counts, a double-precision check before timing, GB/s of bytes moved, and
   an optional group argument (`optimizers`, `line_norm`, `batch_norm`, `api`). PyTorch side:
   `benchmarks/reference/optimizer_normalization.py`; the join script is
   `benchmarks/reference/compare_optimizer_normalization.py`.
7. **Performance work driven by the first comparison**: `[N, C]` batch norm was 7-10x slower than PyTorch
   (double accumulation that MSVC could not vectorize, and loops that reloaded struct members after every
   float store); layer/RMS-norm reductions were not vectorized. Fixed with float group sums, locals and
   `restrict`, and SSE2 intrinsics. Two further attempts made `layer_norm_backward` slower and were reverted.
8. **Docs**: `docs/KERNELS.md` (checkboxes, the status table rows, the file list, the project status
   paragraph), `docs/BENCHMARKING.md` (benchmark table row), `docs/benchmarks/README.md` (index line),
   the result file `docs/benchmarks/vgastan-ryzen5-5500-2026-11-14.md` and this log.
9. Shared header: `src/core/dispatcher.hpp` `OpArgs` got `beta1`, `beta2`, `momentum`, `epsilon`,
   `weight_decay` and `step` (the draft's `gamma`/`delta` were renamed). This touches a file other people

## Not done / open

- **`layer_norm_backward` is slower than PyTorch for shapes below ~1M elements** (0.19x at 32x768, 0.64x at
  1024x768 on one thread). Not explained: probable causes are the recomputed mean/variance (two extra
  passes) and baseline SSE2, but fusing the reductions and tiling the final sum both made it worse. Next
  thing to try: keep mean and rstd from the forward pass when autograd is recording.
- **`batch_norm_backward` on `[N, C]`** is 1.5x - 3.3x behind PyTorch (0.30x - 0.69x; clean rerun). It makes
  three passes over x before the dx pass; saving the statistics from the forward pass is the obvious fix.
- **Adam/AdamW on one thread** are 0.67x - 0.94x of PyTorch's fused kernel; a run-time AVX2 path is the
  likely fix (unverified; `MENSURFLOW_NATIVE=ON` was not measured).
- **Large optimizers should use one thread**: 12 threads are 0.80x - 0.88x of one at 16M elements (memory
  bound). The cutoff is a fixed 32768-element threshold, not a tuned one.
- Not built here: Linux/GCC, macOS, CUDA, Metal. Neither `clang-format` nor `g++` is installed on this PC,
  so the pre-commit hook will format the files on commit; I wrote them by hand to the 100-column style.
- Out of scope: GPU kernels, gradient clipping, Nesterov/dampening, AMSGrad, group/instance norm.
