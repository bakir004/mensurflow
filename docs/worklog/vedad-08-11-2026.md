## Summary

Completed Vedad's weekly assignment for CPU activation backward operations and data
movement, including the stretch gather/index-select operations and the memory-bandwidth
benchmark.

## Implemented

1. Added public and CPU-dispatched backward operations for ReLU, sigmoid, tanh, GELU
   (exact and tanh approximation), and SiLU.
2. Added autograd formulas for GELU and SiLU while preserving explicit unsupported
   behavior for activation backward operations not assigned this week.
3. Added a parallel float32 strided-copy kernel for non-contiguous CPU tensors.
4. Added a tiled, parallel 2-D transpose copy used by `Tensor::contiguous()`.
5. Added metadata-only N-D `Tensor::permute()` with negative-dimension and duplicate-axis
   validation.
6. Added CPU float32 `gather` and `index_select`, including axis normalization, shape
   validation, I64 index validation, bounds checks, and parallel dispatch.
7. Added a large-array memory-bandwidth benchmark with one-thread and all-thread results.

PyTorch was also measured at 2, 4, 6, 8, and 12 threads. The native
`activation_movement_benchmark` then measured the same public APIs in

| Operation | Ours/PyTorch | Ours/NumPy |
|---|---:|---:|
| ReLU backward | 1.47x | 0.51x |
| Sigmoid backward | 4.23x | 0.56x |
| Tanh backward | 1.80x | 1.06x |
| GELU backward | 5.99x | 0.06x |

These are public API timings including result allocation on both sides.
After the comparison, contiguous fast paths were added for `index_select` and
`gather`, and transpose was changed to stage cache tiles before writing the
transposed output. The generic coordinate-reconstruction paths remain for
non-contiguous and shape-mismatched cases. The CPU kernels use OpenMP through
`MENSURFLOW_PARALLEL_FOR`; its `if` clause avoids waking worker threads for
small workloads, and `cpu::set_max_threads()` controls the team size.
Correctness was checked before timing. The existing MensurFlow movement
benchmark completed in Release mode; its 4096x4096 pad case reached 21.654
GB/s at 12 threads.
