# Work log: 2026-11-11

Author: Aldin, with Codex assistance.
Branch: `aldin-branch`; this change is based on `a926230`.

## Summary

Implemented the six RNG/indexing functions originally assigned to Bakir in the
[weekly plan](../weekly/2026-11-11-plan.md), taken over by Aldin: `uniform`, `normal`, `bernoulli`,
`dropout`, `one_hot`, and `embedding`. CPU only, following the existing public API → validation
and contiguous packing → dispatcher → CPU adapter → kernel structure. Forward and backward count
as one function for dropout and embedding. No observability or autotuning changes are included.

## What I did

1. Added standalone Philox4x32-10 and seeded F32 uniform, Box-Muller normal and Bernoulli
   factories. Sample offsets permit exact stream continuation across arbitrary chunk boundaries;
   the sequence is independent of CPU thread count. The dispatcher selects the output dtype and
   device for these input-free factories without changing existing operation placement.
2. Added inverted dropout forward/backward, explicit train/eval, saved Bool masks, p=0/p=1
   behavior and CPU autograd. Autograd saves a private mask, so modifying the returned mask cannot
   alter gradients. Dropped NaN/Inf values become zero.
3. Added I64 one-hot with explicit class count and arbitrary-rank indices. Added F32 embedding
   lookup/backward with I64 indices, shape/bounds checks and autograd. Backward stably groups
   repeated IDs, then assigns disjoint row/feature tiles to threads and sums in input order.
   Memory is O(number of IDs + vocabulary), without per-thread copies of the gradient table.
4. Corrected the existing view/autograd integration needed by both new differentiable ops:
   views share storage but now own gradient state and record their inverse transformation.
   Transpose, permutation, reshape, unsqueeze, broadcast and stepped slices propagate gradients
   into the original tensor's shape. Added regression tests and composed-view cases.
5. Added independent references in `tests/reference/`, kernel/API tests, dispatcher registration
   checks, a shared-harness benchmark and optional native LibTorch reference, plus a paired-log
   Markdown reporting script. Updated `docs/KERNELS.md` checkboxes and status rows and documented
   APIs, execution, benchmarks and the handoff to Aldin.
6. Fixed an existing portable-build blocker: AVX2 store lambdas in packed GEMM now carry the same
   target attribute as their calling kernels. Removed one existing unused movement variable.
   Made packed-GEMM test messages lazy without removing checks or shape/thread coverage; the
   previous success path formatted strings for roughly 147 million output checks.

## Tests, benchmarks and results

- Clean portable Release/OpenMP: **31/31 tests passed**, 36.08 seconds.
- Clean portable Release/OpenMP OFF: **31/31 tests passed**, 34.59 seconds.
- Both complete builds and the native random/indexing benchmark compile without compiler warnings.
  Optional Torch configuration retains its existing Kineto/runtime-search-path warnings.
- Tests include three published Philox known-answer vectors, independent scalar references,
  seed high words, unaligned/high/boundary offsets, chunk equivalence, distribution moments,
  scalar/empty/strided/expanded tensors, errors, cutoff boundaries, and 1/2/3/12 requested threads.
- Dropout tests cover mask mutation, nonfinite inputs, both train/eval modes and weighted autograd.
  Embedding tests cover repeated IDs, cancellation-sensitive parallel accumulation, saved-index
  mutation and gradients through transposed, broadcast and sliced tables.
- Native benchmark smoke checks all eight forward/backward rows against independent references.
  Performance comparisons and their limits are recorded in the
  [measurement report](../benchmarks/aldin-ryzen5-6600h-2026-11-11.md).
- Two native comparison runs, reversed library order and more than three minutes of cooling:
  **384 measured library rows / 96 matching conditions**, all correctness checks passed, empty
  stderr. **44/96 conditions exceed 10% median drift**, so their performance ranking is uncertain.
  Stable large 12-thread ratios (PyTorch time / ours): Bernoulli **6.41x / 6.54x**, dropout
  **6.28x / 6.12x**, normal **1.24x / 1.27x**; embedding forward is within 5% of PyTorch.
  Large single-thread normal is **4.31x / 4.30x slower**. The report retains both medians/minimums
  for every size/thread count and a measured copy-bandwidth comparison.
- Portable and native benchmark modes both pass `--help` and reject nine malformed CLI cases.
  The paired-log parser validates eight smoke-operation rows and renders matching Markdown columns.
- Portable GCC vectorization diagnostics confirm the embedding accumulation inner loop and several
  fill/copy/dropout-backward paths vectorize. Philox/transcendental generation remains scalar
  within each parallel block; no explicit SIMD speedup or tuned threshold is claimed.

## Not done / open

- GPU kernels, additional dtypes, random permutations, general gather/index-select backward,
  observability and autotuning are outside these six functions.
- `one_hot` returns I64, matching the reference. Existing `cast` does not convert I64 to F32;
  a future cross-entropy gradient must handle integer labels internally or extend casting.
- Existing general autograd graph scheduling still consumes a nonleaf node on its first backward
  propagation; arbitrary shared nonleaf DAGs are not addressed here. A copying public
  `contiguous()` also retains its existing gradient-detachment behavior. The new operations pack
  inputs internally while recording their original parents, so their tested view chains work.
- Further SIMD and per-operation cutoff tuning require stable measurements on the team's other
  CPUs. Current loops retain the project's conditional OpenMP convention.
- Normal's portable scalar double-precision Box-Muller transform is behind PyTorch at small
  sizes and 1–2 threads; vectorized Philox/transform batches are a candidate for a later pass.
  Small embedding backward is about 2x behind at 6/12 requested threads because stable grouping
  and table initialization dominate; a direct serial scatter below the cutoff is worth measuring.
  Repeat the 44 noisy conditions in a controlled session before drawing performance conclusions
  or changing defaults.
