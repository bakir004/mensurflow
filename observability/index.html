Kernels

Each cell is the median time of one public call with data on that device (GPU devices run with Execution::GPU), and the rate it implies: GB/s of inputs + output for memory-bound ops, GFLOP/s for matrix products. The fastest cell per op is marked. Greyed cells have no registered kernel. Click an op for its page: results, size sweep and call breakdown.
The CPU runs each kernel three ways: sequential (1 thread, from a copy of the library built without auto-vectorization, observe_scalar), SIMD (1 thread, normal build) and threaded SIMD (the Threads setting, default all; this is the plain cpu:0 result). The gain columns divide their times: SIMD = sequential / SIMD, threads = SIMD / threaded, total = sequential / threaded. Hand-written intrinsics (the x86 AVX2 GEMM kernel) and libc's memcpy stay vectorized even in the sequential build.

Call breakdown

One call

Each bar is a span, and the bars under it ran inside it. call runs from entering the op until its result can be read. It splits into the op function returning and read result, which waits for the device. Inside are the library's spans: the dispatcher (named after the op), the kernel, and every allocation and copy.

Where the time goes (self time, mean over calls)

Self time is a span's time minus the spans inside it. For example, the op function's self time is its argument checks and setup. The self times add up to the whole call.
